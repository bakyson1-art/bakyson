## 2. Authentication & session security

### Password storage

| Control | Implementation | Status |
|---------|---------------|--------|
| Hashing algorithm | bcryptjs | ✅ |
| Hash cost | 10 (db-setup.mjs) / 12 (admin-account.mjs) | ⚠️ Inconsistent — unify to 12 |
| Salt | Auto-generated by bcrypt | ✅ |
| Plain text passwords | Never stored or logged | ✅ |
| Password policy | None enforced client-side | [TBD] min length, complexity |

### Session management

| Control | Implementation | Status |
|---------|---------------|--------|
| Session strategy | JWT (next-auth v4) | ✅ |
| Session cookie | next-auth managed, `httpOnly`, `secure` in production | ✅ |
| `NEXTAUTH_SECRET` | Required env var | ✅ set locally, [TBD] production |
| `NEXTAUTH_URL` | Must match production domain exactly | ⚠️ `.env.example` points to Railway URL — fix before production |
| Session fixation | new session issued on sign-in | ✅ (next-auth default) |
| Sign-out | Clears session cookie | ✅ |

### Known auth bug

`pages.signIn` in `nextauth` config points to `/portal/login`, which does not exist. The actual sign-in page is `/portal`. Unauthorized access to `/portal/projects` or `/portal/tickets` will redirect to a 404. Fix before production.

## 7. Threat model

### Threat: Credential stuffing / brute force on portal
- **Mitigation:** bcrypt hashing, rate limiting on password reset, account lockout not implemented
- **Gap:** No account lockout after N failed login attempts. next-auth v4 credentials does not lock out by default. [TBD]

### Threat: Email harvesting via contact form
- **Mitigation:** None beyond Zod email validation
- **Gap:** No CAPTCHA or honeypot. [TBD] consider Turnstile or reCAPTCHA

### Threat: Data exfiltration via API
- **Mitigation:** Parameterized queries, Zod validation, middleware session protection on portal routes
- **Gap:** `/api/projects` and `/api/tickets` lack server-side session validation; rely on middleware only

### Threat: XSS via user-submitted content
- **Mitigation:** React auto-escapes output; no `dangerouslySetInnerHTML` found in audit
- **Gap:** Contact form submissions stored as plain text; if rendered elsewhere without escaping, XSS risk

### Threat: Supply chain compromise
- **Mitigation:** `npm ci` in CI (lockfile-pinned), Dependabot not configured
- **Gap:** No Dependabot or automated vulnerability scanning. [TBD]

- [ ] `npm run build` passes (TypeScript clean)
- [ ] No `bakyson.com` references
- [ ] No hard-coded secrets in code
- [ ] `.env.local` is gitignored and not committed
- [ ] All public POST endpoints have Zod validation
- [ ] Rate limiting verified on public POST endpoints
- [ ] `NEXTAUTH_URL` matches production domain
- [ ] `/portal/login` redirect bug fixed
- [ ] Sentry DSN configured in production
- [ ] Database backups verified
